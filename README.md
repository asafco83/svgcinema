(Formerly Keyline.)

A browser-based SVG animation editor. You draw or import artwork, animate it on a keyframe timeline, and export **one self-contained animated SVG**. The SVG plays with a small built-in JavaScript player or with pure CSS.

## Getting started

```bash
npm install
npm run dev        # http://localhost:5173 with hot reload
npm test           # unit tests (Vitest)
npm run typecheck  # TypeScript, no emit
npm run build      # type-check + production build into dist/
npm run preview    # serve dist/ locally
tests/browser/run.sh  # browser tests (Playwright for Python), see tests/browser/README.md
```

Requires Node 18 or newer (developed on Node 22).

## How the pieces fit

**The runtime is embedded by serialising a function.** `export/build.ts` writes `CinEngine.toString()` into each exported SVG.

- **Keep it self-contained.** `src/runtime/engine.ts` must not import anything or touch module scope.
- **The test guards this.** `tests/engine.test.ts` rebuilds the function from its source text and runs it.
- **The build target protects it.** Vite builds for ES2019, so the bundler never injects helper functions into it.

**Modules have no side effects on import.** Each module only defines functions and constants. Event listeners and other setup live in an exported `init()`, and `src/main.ts` calls the `init()` functions in a fixed order. This keeps the circular imports between UI modules safe.

**Shared mutable state uses setters.** ES module imports are read-only bindings, so replacing the open document goes through `setDoc()` and the canvas engine through `setEng()`. Other examples are `setIdc()`, `nextAid()` and `setLastExport()`. Reading `doc` anywhere always gives the current document.

**The editor canvas renders the exact SVG that gets exported.** `render/markup.ts` produces markup for both, and the canvas is animated by the same runtime that ships in the file. What you see while editing is what you get.

## The sample scene

The editor opens with a sample scene (also under File → New → **Open sample scene**). It doubles as a tour of what SVGcinema can animate; select a layer to see how it's done:

- **Sky**: an animated linear gradient, night to dawn. **Night sky**: star shapes with an animated corner radius, a blink made of hold keyframes and an elastic pulse; **Sparkle** is a symbol with two instances sharing a pulsing dot, the second starting 0.15 s later; the group fades out.
- **Sunrise**: a group rising as one. **Glow** has a radial gradient, an animated blur filter and screen blending; **Rays** spin and scale; the **Sun** changes colour.
- **Blob** morphs between shapes with a custom easing curve. **Comet** follows a curved motion path and turns along it; **Comet trail** shows travelling dashes (an animated dash offset) that stretch and shrink (an animated dash pattern).
- **Hills** is a clipping group: the drifting **Mist**, which grows as it goes (an animated size) along an arc at an even speed, only shows inside the hill silhouette (the **Clip path** folder).
- **Sprout** is a bone rig: three bones carry the stalk, leaves and flower, and sway with follow-through; the top bone squashes and stretches as it swings. The **Leaf** is pinned: one pin holds its base while the other flutters its tip. The **Tendril** beside the stalk is bent by the rig: its pins follow the three bones. The rig has its own draw order: the **Leaf** hangs on the second bone but is drawn behind the **Stalk**.
- **Flag**: the **Pole** is a line whose end grows; the **Pennant** is a polygon with a gradient, a skew wave and an animated corner radius. The whole flag bends in the wind with pins, through a triangle mesh.
- **Landscape**: **Horizon** draws on with Trim path; **Signature** is a mask group (masking by brightness) whose gradient wipe reveals a line that links to this editor.
- **Title** slides and fades in with an animated drop shadow.

`tests/sample.test.ts` checks the scene keeps showing all of these.

**Selecting on the canvas:** click a layer (the outermost one; Ctrl+click picks inside a group, Shift+click adds or removes). Drag from an empty spot for a **marquee**: every top-level layer it touches is selected when you let go (each gets a dashed outline while you drag); Shift adds them to the selection or takes them out, Ctrl picks the shapes inside groups. A click on an empty spot deselects. Alt+drag a layer drags a copy, leaving the original (one undo step). Ctrl+A selects every top-level layer that is shown and unlocked (every keyframe while you work in the timeline); Ctrl+Shift+A deselects.

**Keyboard shortcuts** (F1, the keyboard button in the top bar, or Help › Keyboard shortcuts) lists every shortcut in five tabs that follow the main menu, each in titled sections: General (File, Edit, Help), Layers (Select, Organise, Transform, Colour), Tools (Tools, Drawing, Bones and pins), Animation (Playback, Keyframes, Easing, Animate a property) and View (Zoom, Pan, Panels, Show and hide). The search box looks across all of them and says where each hit lives; the tool and Animate keys come from the real bindings, and on a Mac Ctrl and Alt show as ⌘ and ⌥. Letter shortcuts go by the physical key, so they work on any keyboard layout (Ctrl+Z is undo with a Hebrew or Russian layout too). Besides the ones below: Ctrl+H hides or shows the selection, Ctrl+↑ / ↓ bring forward / send backward (with Shift: to the front / back), Ctrl+X cuts the selected keyframes, Shift+Space stops and goes back to the start, I / Alt+I pick the fill / stroke colour from the screen (browsers with an eyedropper), / closes or opens every inspector section, Alt+G turns the front grid on or off, Alt+O the onion skin, and Ctrl+scroll over the timeline zooms it around the pointer.

The interface's own text (labels, menus, the layer list) can't be highlighted, so a stray drag or Select all never paints it; fields, text you type and code views can be selected as usual.

**Zoom:** click the percentage at the bottom of the work area for a menu with a slider (2%–3200%), a typed value, _Fit selection_ (2), _Fit_ (1), _Zoom 100%_ (0), _Zoom in_ (Ctrl +) and _Zoom out_ (Ctrl −). The − / + buttons beside it step the zoom; Ctrl+wheel zooms at the pointer.

**Work area:** the artboard shows the project name and canvas size above its top-left corner. **Inspector** (properties of the selected layer):

- **Header:** the layer's name (click to rename) and type.
- **Sections** open and close: click a section's heading (or its chevron). Closed sections stay closed for every layer and after a reload.
- **Keyframe toggles:** every animatable property has its own row and its own ◆, so colour and opacity, for example, animate separately. The ◆ shows three states, explained in the Transforms heading: a grey outline when the property isn't animated, amber with an amber label when it is, and filled amber when there is a keyframe at the playhead. Click it to add or remove the keyframe at the playhead.
- **Align bar** at the top: align left / centre / right / top / middle / bottom, distribute horizontally / vertically. One layer aligns to the canvas, several align to each other; distributing needs three or more. Below it, the boolean operations (union, subtract, intersect, exclude) for two or more shapes or paths; with fewer selected they grey out and a note says what they need.
- **Text:** content (spell-checked by the browser, here and when typing on the canvas, with a red wavy underline and the browser's suggestions on right-click; a double-click on the text underlines its misspelt words straight away; Help ▸ Spell check turns it off), position and measured size. **Convert to shapes** turns the letters into one path layer (same name, place, style and animation) when the font is a Google Font or a font on this computer; basic font stacks look different on every computer, so they can't. Hebrew is drawn in its right-to-left order; Arabic-script text, whose letters join, can't be converted yet.
- **Size** (rectangles, ellipses, images and paths, including polygons, stars and lines): width and height as you see them (the shape's own size times its scale, so scaling updates them; a value typed in is divided back by the scale), live on the canvas while you drag the W / H labels, animatable with its own ◆. The shape grows and shrinks around its origin (put the origin on an edge or corner with the anchor grid to grow it from there). Unlike Scale, Size changes the shape itself, so the stroke width stays the same. The link toggle beside the fields keeps the proportions, as for Scale (on by default for images, off for shapes). Text and groups use Scale.
- **Shape settings** (at the top for these shapes): polygon _Sides_; star _Points_ and _Ratio_ (inner / outer radius); corner _Radius_ for rectangles, polygons and stars (capped so corners never overlap, and animatable: the runtime rebuilds the rounded path every frame); line _From_ / _To_, each keyable on its own so a line can grow or swing. Polygons and stars keep their settings until their nodes are edited by hand or they get Morph keyframes; then they are plain paths.
- **Number fields:** drag the label at the left of any number field (the X in X 162) left or right to change the value: one unit per pixel, Shift ×10, Alt ×0.1 (finer steps for small units such as seconds). A drag is one undo step; a plain click on the label puts the caret in the field. Toggles beside a pair of fields (keep proportions, rotate along the path, centre origin) have a column of their own, so every pair of fields keeps the same width.
- **Transforms:** position, scale (with a keep-proportions link), skew X/Y, rotate as turns + degrees (with a _rotate along the motion path_ toggle when the layer has one), origin, anchor grid, flip.
- **Motion path:** _Set motion path_ makes the layer follow a path, rectangle or ellipse over the whole animation (one keyframe per point, timed for an even speed). _Even speed along curves_ moves along each curved segment at a constant speed (by its length, as SVGator does) instead of following the curve's own spacing. On the canvas, drag a segment of the path to curve it, drag its handles to fine-tune, double-click a segment to straighten it. **Path node** (below it) edits the keyframe at the playhead, or the one before it: its type (straight, mirrored, asymmetric, disconnected) and position; ‹ › step between nodes. Alt-drag a handle to move it alone.
- **Text appearance:** **font**: the field opens a searchable list, one line per font: its name on the left and, on the right, the layer's own text in that font (or “Sample” in its script: דוגמה, Пример, ★ ✦ ☀… when the font lacks those letters). Chips filter by type (serif, sans, display, script, mono) and a menu by script. The list holds Favourites (★, remembered in this browser), Recent (the last five fonts chosen), the basic system stacks, 36 Google Fonts grouped by script (Hebrew, Latin, Cyrillic, Greek, Arabic, Symbols; a font covering several scripts is listed under each, and the group headings stay pinned while you scroll), and fonts on this computer (Chrome/Edge can list them after you allow it; elsewhere type a font name). Preview faces load as their rows scroll into view. Arrow keys and Enter choose, Esc closes. Then style (weight × italic), bold / italic / underline / overline / strikethrough, size, letter spacing, alignment, **direction** (left to right / right to left: automatic from the first letter until you pick one; the Align buttons stay as you see them, and right-to-left text starts at the right, so it grows leftwards as you type), **case** (as typed, UPPERCASE, lowercase, Capitalise Each Word: the typed text is kept, only its display changes), line height, and **Keep width**: when on, the box keeps its width and lines break to fit it.
- **Fill & stroke:** each colour row has a swatch, an eyedropper and the value as text (a colour, `none`, or _Linear_ / _Radial_ for a gradient). Click the swatch to open the colour window. Its top row picks the type: _None_, _Solid_, _Linear_ or _Radial_.
  - **Colour:** saturation/brightness area, hue and opacity sliders, an eyedropper (in browsers that support it), and Hex / R G B / A fields. Changes show live; clicking outside or pressing Esc closes the window as one undo step.
  - **Gradient editor:** drag stops along the bar and click it to add one. The colour part edits the selected stop. A stop has a colour, opacity and position. Linear gradients have an angle; radial ones have a centre and radius.
  - **On the canvas:** while the window edits a gradient, the shape shows its handles. Linear: drag the start (hollow) or end (filled) point, or the bar to move both; Shift keeps 15° steps. Radial: drag the centre, the round handle for size and direction, and the square handle for the other radius (an ellipse).
  - **Animating:** gradients animate like colours, blending stops, angle, centre and radius, and even fading from a solid colour. In CSS-only exports, gradients animate their stop colours only.
  - **Other controls:** fill and stroke opacity, stroke width, and a swap button. The document background uses the same window (None or Solid).
- **Appearance:** _Trim path_ (Start / End / Offset %, all animatable) shows part of a stroke, for draw-on and travelling-dash effects. Also: paint order, blending, isolate, opacity slider, line ends, line join, miter limit, dash pattern (animatable: patterns of different lengths blend by repeating to a common length, and no pattern blends as zeros, as in SVGator), dash offset, path length. (To draw a line on, animate Trim End from 0% to 100%: Shift+D.)
- **Filters:** blur and drop shadow, reorderable, every parameter animatable (in JS export mode; CSS mode exports filters as static).

**Typing text:** double-click a text on the canvas (or click it with the Text tool) to type in place. The real text stays visible with all its styles while you type; the panel's text box updates the canvas live too. While typing, the box has a handle on each side: drag one to set the width (Keep width turns on and lines wrap). When the text is only selected, its handles scale it like any layer. Space types a space while you edit. Esc, Ctrl+Enter or clicking away finishes. With the Text tool, click for text that grows as you type, or drag to draw a box of fixed width whose lines wrap.

**Right-click menu** (on the canvas or in the Layers panel), modelled on SVGator's:

- **Copy / Paste:** Cut, Copy, Paste, Paste in place, Duplicate.
- **Layer commands:** Group, Ungroup, Delete, Center origin, Animate, Set motion path, Hyperlink, Convert to path (Convert to shapes for text), Export selection.
- **Masks:** Create clipping path, Create mask, Release mask.
- **Placement:** Align, Arrange, Lock, Rotate 90°, Flip horizontal / vertical.

Shortcuts: Ctrl X / C / V, Ctrl ⇧ V (paste in place), Ctrl ⇧ O (center origin), Ctrl ⇧ P (convert to path), Ctrl ⇧ E (export selection), Ctrl L (lock), Ctrl ⇧ ] / [ (bring to front / send to back). Ctrl C / V copy keyframes when keyframes are selected, and layers otherwise.

**Editing several layers:** with more than one layer selected, the inspector shows only the properties all of them have (transform, opacity, fill & stroke and stroke style when they are all shapes, compositing). A value they share is shown; one that differs reads _Mixed_, and a colour swatch shows •••. Typing a value, dragging a field's label, picking a colour, a toggle or the ◆ applies to every selected layer, as one undo step; for X / Y pairs each layer keeps its other value.

**Animation presets** (Animate ▸ _Presets…_ in the Layers panel or the main menu): ready-made animations for the selected layers, starting at the playhead. Groups: **Entrances** (fade in, slide up / down / left / right, pop in, zoom in, drop in, rotate in, flip in, elastic in, spiral in, skew in, unfold), **Exits** (the same, out; fold for unfold), **Emphasis** (pulse, pop, wiggle, shake, spin, swing, blink, heartbeat, bounce, rubber band, jello, tada, float, flicker, head shake, breathe, wobble, squash, glitch), **Strokes** (draw on, erase, travel, draw from middle, stroke pulse, undraw: shapes and paths), **Colour** (flash, dim, stroke flash, colour pulse) and **Filters** (blur in, blur out, glow pulse, shadow lift, soft focus; they add the blur or shadow they need, and play in JS exports only: a CSS export keeps filters still, so they carry a _JS_ badge). Only the presets that fit the selection are listed. Each tile plays its preset on a small shape and names the tracks it animates (e.g. _Position · Opacity_). A preset writes keyframes only for the properties it animates and only inside its span, replacing any keyframes of those properties already there: entrances end on the value the layer already has, exits start from it, emphasis starts and ends on it, so presets slot into an existing animation. Hovering a tile previews it on the timeline (its span shaded on each layer, the keyframes it would replace outlined in red); the line beside Apply says the same in words (how many keyframes it replaces, in red). _Length_ (each preset has its own default), _Stagger_ (several layers start one after another) and _Strength_ (how far it moves, grows or turns) adjust it. Double-click a tile, or Apply, to use it: one undo step, and the toast says how many keyframes it replaced, with an Undo button. A preset that runs past the end lengthens the animation.

**Graph editor** (the timeline bar's _Graph_ button): one track opens into a value graph across time, under the playhead and keyframes like the rest of the timeline. It shows the selected keyframe's track, else the selected layer's first number track; click another property's name to graph that one. Number properties only (opacity, rotation, stroke width, trim, filter amounts…, and points such as position, scale or size, drawn as X and Y curves in two colours); colours, gradients, dash patterns and morphs have no graph, and their names say so. Drag a key to change its value and time (Shift keeps the drag to one direction), with the time and value shown as you drag. The selected segment (after the selected keyframe, or under the playhead) shows its easing handles: dragging one makes a custom cubic-bezier, shared by X and Y. Beside the graph, the property's values at the playhead (they follow it); click a key for the easing presets in the Keyframe panel. One undo step per change.

**Onion skin** (the timeline bar's _Onion skin_ button, View ▸ Onion skin, Alt+O): outlines of the selected layers a few steps before (blue) and after (red) the playhead, fading with distance. The arrow beside the button sets how many frames before and after, the time between them and the strength of the nearest ones (remembered in this browser). The ghosts are drawn only on the canvas, never exported, and hidden while playing.

**Symbols:** reusable artwork whose instances share their contents. _Element ▸ Make symbol_ turns the selected group (or a new group of the selected layers) into a symbol; Duplicate (Ctrl+D) or Alt+drag an instance for more, or click the symbol in **Assets ▸ Symbols** (a card per symbol with a live thumbnail and its instance count; double-click the name to rename it, ✎ to edit it, × to delete it, which asks first when it has instances and leaves them as plain groups). Instances are marked in the Layers panel (the symbol icon and ×N) and in the inspector (_Symbol · N instances_). Each instance has its own transform, opacity and keyframes; shapes, styles and the contents' animation are shared. **Editing a symbol:** double-click an instance (or Element ▸ Edit symbol, or _Edit symbol_ in the inspector): the rest of the scene dims and can't be picked, the other instances show as dashed outlines, and a chip on the canvas names the symbol with _Done_ (Esc, or a double-click on an empty spot). A change there reaches every instance (one undo step). The inspector's **Instance** section has a _Time offset_ (this instance's contents start later), _Edit symbol_ and _Detach instance_ (it becomes a plain group). The JS export writes each instance's contents once and the other instances with the same time offset as `<use>` of them, which the player animates for all; the CSS export, and offset instances, are written out in full.

**Masks:** select two or more layers, then choose _Create mask_. The top layer goes into a _Masks_ folder inside a new _Mask group_, and the other layers show only where the mask is.

- Masks work by opacity, so soft and semi-transparent masks behave as expected. _Mask by_ (in the mask group's Group section) switches to **Brightness**: the mask shows the layers where it is light, white fully and black not at all, as SVG masks and SVGator do.
- A _clipping path_ uses only the mask's shape.
- Mask layers stay normal layers: select them in the Layers panel to move, edit or animate them. A drag inside the selection box moves them even though they aren't drawn.

**Boolean operations** (second row of the align bar, or right-click ▸ Boolean): select two or more shapes or paths.

- _Union_ combines them.
- _Subtract_ cuts the upper ones out of the bottom one.
- _Intersect_ keeps only the overlap.
- _Exclude_ keeps where they don't overlap.

They're combined as they look at the playhead into one new path, which takes the bottom layer's place and style. Undo restores the originals.

**Posing a rig:** with _Key whole rig_ on (the default; it sits in the Bone section of the rig's top bone), dragging any bone (FK, IK or Scale bone) keys every bone of the rig at the playhead, so each pose is stored whole. The new keys hold the values the bones already had there, and the easing they split is split with them, so nothing else in the animation changes. Turn it off for overlapping action (only the bone you drag is keyed). Turning it on for a rig whose poses have keys on some bones only offers to _Add keys_: every bone gets a key at each of the rig's key times, again without changing the motion; turning it on and adding the keys is one undo step. In the timeline, the top bone has a **Pose** row with a diamond at every time any bone of the rig has a key: click one to select all of them, drag to retime the pose, Delete to remove it.

**Bending with pins:** each pin pulls the path's nodes (and their handles) with it, nearer nodes more than far ones; a pin can also turn, bending the path around it. A pin that doesn't move holds the path in place. The **Pins** section of the inspector has a button per pin; the rows below it edit the selected pin: _Position_ and _Rotation_, each with its own ◆, and _Reach_, how far every pin of the path pulls (100% by default). _Remove pin_ and _Remove all pins_ take them off (the path keeps its rest shape). In the timeline each pin has its own rows (_Pin 2_, _Pin 2 · Rotation_). Both exports bend the path: the JS player computes it, and the CSS export animates the path's shape with SMIL, as for morphs.

**A rig's own draw order:** nesting decides stacking, so a part can't normally sit behind its parent's artwork (a far arm behind the torso while it hangs on the torso's bone). Turn on _Own draw order_ in the Bone section of the rig's top bone: a list of the artwork attached to the rig's bones appears, front at the top, starting in the order nesting draws it. Reorder it with the arrows or by dragging a row; the canvas and both exports draw the artwork in that order, each piece still moving with its bone (the Edit bone tool's rest pose too). Turning it off goes back to nesting. Artwork attached to the rig later goes in front. The order is not animated.

**Pins that follow bones** (Pin tool › _Bind to bones_) sit at a bone's joint and move and turn with the bone, so a rig bends a sleeve, a tail or a vine without keyframing the pins: the Pins section names the bone instead of Position and Rotation. Both exports follow the rig: the JS player works out where the bone is each frame, and the CSS export bakes the result like any other bend.

**Pins on images, text and groups** bend them through a triangle mesh, which the Pin tool draws over the artwork. The mesh is an even lattice of equilateral triangles laid over the content (and everywhere content inside a group moves during the animation, plus room for strokes and filters); triangles with nothing in them are left out, and the mesh is rebuilt by itself when the content changes. Each triangle shows the artwork clipped to it and moves it by the affine map its three corners give, so gradients, filters and text bend too and text stays editable. _Mesh_ in the Pins section sets the density (it shows how many triangles the mesh has): a denser mesh bends more smoothly and costs more. The JS export computes the triangles every frame; the CSS export moves each one with SMIL, which stores every frame, so the Export dialog offers _Use JavaScript_ when that is much smaller (it does the same for morphs). With the hover trigger, CSS mode animates the triangles with CSS, where faint seams can show between them in Chrome, and content inside a pinned group keeps playing when the pointer leaves. A pinned group's layers can't be picked on the canvas (use the Layers panel).

**Snapping, grid, rulers and guides** (the magnet and grid buttons in the canvas bar):

- **Snapping** (Alt+S turns it on or off) works while moving and drawing. It can snap to objects (the edges and centres of other layers and of the canvas), to points (path nodes), to guides, to the grid, and to whole pixels. Matches show as magenta lines, and holding Ctrl/Cmd skips snapping.
- **Grid:** a back grid sits behind the artwork and a front grid over it. The grid size is set in the grid menu.
- **Rulers** (Alt+R): drag from a ruler to make a guide.
- **Show bones** (Alt+B) shows or hides bones on the canvas, together with a dotted link from a bone to each bone bound to it with the Bind tool, from the parent bone's joint (its start) to the bound bone's joint. A bone that starts on its parent's tip (a connected chain) needs no link. The links are only a guide on the canvas: they are never exported.
- **Show pins** (Alt+P, on by default) shows every pinned layer's pins outside the Pin tools: the selected layer's at full size, the others smaller and fainter; pins bound to a bone are red. With the Select tool, the selected layer's pins work as with the Pin tool, everything but adding pins: the mesh and rest marks show, drag a pin to bend (keyed at the playhead), drag the selected pin's ring to turn it, Alt+drag to move it at rest, and Delete right after picking a pin removes it (otherwise Delete is the layer's). Another layer's pin is picked with a click (selecting that layer) or dragged. A bound pin is only picked, since its bone moves it. Adding pins stays with the Pin tool, and Edit nodes shows none (it shows the rest shape). In the Pin tools the other layers' pins show for reference only. Pins are drawn on top of the selection box, so on a small layer they win over its handles. Off: pins show only with the Pin tools, as before.
- **Guides** (Alt+L shows or hides them): drag a guide to move it, or drop it on a ruler to remove it. _Clear guides_ removes them all.

The guides are saved with the project; the other view settings are remembered in this browser.

**Hyperlink:** gives a layer a link (web address, mailto:, tel: or #anchor) that opens in a new tab or the same one. Clicking the layer in the exported SVG follows it.

**Timeline follows the selection:** selecting a layer (on the canvas, in the Layers panel or anywhere else) scrolls the timeline so its row and its property rows are in view; a layer already in view leaves the timeline where it is.

**Timeline height:** drag the timeline's top edge up or down. At its smallest it shows just the controls and the time ruler; at its largest it leaves a strip of the work area. The height is remembered in this browser; double-click the edge for the default height. With the edge focused, ↑/↓ resize it by 16px (Shift: 64px), Page Up / Page Down go to the largest / smallest, Home to the default. Resizing keeps the canvas zoom percentage and leaves the artwork where it is on screen; only in the fit view (_Fit_, 1) is the artboard fitted to the new size.

**Timeline length:** the timeline always fills its panel, past the end of the animation (that part is shaded). The white line marks the end: drag it to change the length (it snaps to 0.05s; Shift for 0.01s) and a tag shows the length while you drag. The Length box follows along, and typing in it still works. With the end line focused, ←/→ change the length by 0.1s (Shift: 1s).

**Freezing a track:** hover a property row in the timeline and click the snowflake, left of the property name. The track keeps its keyframes but stops using them: the property holds the value it had at the playhead, the row and its keyframes turn grey, no keyframes can be added, and exports leave it out. Editing the property meanwhile changes the held value. Click the snowflake again to unfreeze and go back to the keyframes.

**Moving keyframes:** with two or more position keyframes selected in the timeline (or one at the playhead), dragging the layer or using the arrow keys on the canvas moves all of them together (select them all to move the whole motion path). A single key selected at another time, such as the one _Animate_ makes and selects, doesn't count: moving the layer keys its position at the playhead. Arrow keys pressed while working in the timeline still move the selected keyframes in time.

**Web fonts in exports:** Google Fonts are converted to outlines by default (no font download, identical everywhere, also inside `<img>`). _Embed font_ instead keeps live, selectable text and embeds only the alphabets the text uses, which is smaller for long text. Hebrew is drawn in its right-to-left order; Arabic-script text is always embedded so its letters join. Fonts from this computer are converted or embedded the same way once the browser has shared them (embedding includes the whole font file); otherwise the SVG only names the font.

## Opening and importing SVG

**Open…** (Ctrl O) also opens `.svg` files: the SVG becomes a new project with its canvas (viewBox), its title as the project name, and its artwork as editable layers. It isn't saved yet (Save makes a `.SVGcinema` file). **Import files…**, dropping an SVG on the canvas, pasting SVG markup and placing an SVG from **Assets** read the file the same way into the current project, inside a group named after the file (the project's canvas and settings stay).

- **Layers:** groups keep their hierarchy, order and names (SVGator names, Inkscape labels, `data-name`, meaningful ids; other layers are named by kind, e.g. _Rectangle 1_).
- **Transforms** become position, rotate, skew and scale; each layer's origin goes to the middle of what it draws.
- **Shapes** stay shapes (rectangles keep their corner radius, circles become ellipses, polygons, polylines and lines become paths) with their fill, stroke, opacities, dashes, line ends and joins, all editable. Colours from stylesheets (`<style>` classes) and inherited from groups are resolved. Linear and radial gradients (user-space or box units, transformed or not) become editable gradients.
- **Text** stays text: lines (tspans one under another) become one text with its line height; lines placed apart become a group of texts. SVGator's embedded fonts map to the same Google Font (e.g. Roboto).
- **Images** embedded in the file go to Assets and become image layers (sized as the browser draws them).
- **Clip paths and masks** become clipping and mask groups (SVG masks mask by brightness).
- **Filters:** a blur or a drop shadow becomes an editable filter; other filters, patterns, markers and text on a path are kept as they are. Anything that couldn't be made editable is listed in a short report after the import.

**Open recent** lists the last 8 projects you opened or saved, newest first, with when. In Chrome and Edge an entry opens the file itself (the browser may ask for permission again; a file that was moved or deleted drops off the list). Elsewhere, where the browser can't reopen files, it keeps a copy of the project as it was when last opened or saved (the newest 4 copies), and Save then writes a new file. The list stays in this browser; _Clear the list_ empties it.

**File names in any language:** the project name (Hebrew, Russian, Japanese…) is used as typed for the `.SVGcinema` file and the exported `.svg`; only the characters file systems refuse (`\ / : * ? " < > |`) are left out. Code identifiers (component names in the embed code) still use a plain Latin form.

**Less motion:** the Export dialog's _Less motion_ setting decides what visitors who ask their system for reduced motion see: _Play normally_ (the default, adds nothing), _Show the first frame_ or _Show the last frame_. The JS player then holds that frame and doesn't start (whatever the trigger); a CSS export pauses every animation on it (a few bytes of CSS). Shape morphs in a CSS export are held with the CSS `d` property, which Safari ignores, so there they keep playing.

**SVGs exported by SVGcinema:** tick _Include the editable project_ in the Export dialog (off by default; it shows how much it adds, about a third more for a typical JS export before compression). The project goes into the SVG's metadata, the pictures stay the SVG's own, and opening the SVG in SVGcinema brings back the exact project (layers, keyframes, settings); exporting it again gives the same file. Added to another project, its layers come in a group. Without it, an exported SVG opens as its artwork (the first frame), not animated.

**Animated SVGs from SVGator** keep their animation as ordinary, editable keyframes (opened as a project, they also bring their length, repeat, direction, fill mode, speed, frame rate and start trigger; added to a project, they lengthen its timeline when they are longer).

- **JS player exports** (embedded or external player): the keyframes and their easing come across exactly — position along the motion path (SVGator moves along curves at an even speed: _Even speed along curves_ is on), rotate, skew, scale, the anchor point (as Origin), opacity, fill and stroke (colours and gradients; where SVGator switches between two gradients or from no paint, so does the import), fill / stroke opacity, stroke width, dash offset, dash pattern, size (growing from the shape's corner, as in SVGator), corner radius, shape morphs, line ends and blur. The result plays like SVGator's own player: the browser tests compare the positions against it to within a pixel. An anchor point that moves while following a curved path is placed within about a pixel.
- **CSS exports:** the groups SVGator wraps around an animated element (move / rotate / skew / scale) fold back into the one layer, the motion path comes back from `offset-path` with its curves, and the CSS keyframes (with their per-keyframe easing) become the same keyframes the JS export gives. SVGator's CSS writes the anchor point's offset twice, which shifts animated elements in browsers (in its own preview too); the import reads it once, so the result matches the JS export. Its CSS blur amounts are converted back as well. (SVGator can't export shape morphs as CSS.)
- **Other CSS animations** in an SVG (`@keyframes` on elements) also become keyframes: opacity, fill and stroke, their opacities, stroke width and dashes, sizes, and transforms written as translate · rotate · skew · scale around a `transform-origin`.

## The `.SVGcinema` project format

A `.SVGcinema` file is a standard zip archive:

| Entry                      | Contents                                                                                                              |
| -------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| `thumbnail.png`            | The first frame, 512 px on its long side: the first entry, stored uncompressed, for file managers' thumbnail handlers |
| `manifest.json`            | `format: "svgcinema-project"`, version, name, save time, canvas size, counts                                          |
| `project.json`             | The document: layers, keyframes, easing presets, export settings                                                      |
| `assets/index.json`        | One entry per asset: id, name, kind, MIME type, size in pixels and bytes, file path                                   |
| `assets/<id>-<name>.<ext>` | Each image as its original file                                                                                       |

`project.json` references assets by id, so images are stored once.

**Thumbnails in your file manager:** optional add-ons read `thumbnail.png` so projects show their first frame instead of a plain icon:

- **Windows** File Explorer: `SVGcinema-Thumbnails-Setup.exe`. It installs for you only, with no administrator rights. It's unsigned, so Windows may warn about an unknown publisher: choose _More info_, then _Run anyway_.
- **Linux**: `svgcinema-thumbnails.deb`, or the `.tar.gz` with `install.sh`. Works in GNOME Files, Nemo, Caja and Thunar.

The editor links to them from **Help › Thumbnails on your computer…** (hidden on a Mac, which isn't supported). It offers the download for the system you're on first, with the Windows warning highlighted. The website has a section with both. Downloads are in the [`thumbnails` release](https://github.com/asafco83/svgcinema/releases/tag/thumbnails); the sources and how they work are in `thumbnailers/`.

## Typing

The document model lives in `src/model/types.ts`: `Doc`, `Layer`, `Geometry`, `BaseValues`, `Tracks`, `ExportSettings`, `Asset`, plus the transient `EditorState` (`S`) and `Drag`. The runtime's `EngineLayer` is the exported subset of `Layer`.

`tsconfig.json` is `strict`, including `noImplicitAny`, with two exceptions:

- `strictNullChecks` is off;
- `useUnknownInCatchVariables` is off.

Explicit `any` remains where the code works with the page directly: `$()` and `byId()` lookups, a few panel elements in `core/dom.ts`, and `e.target` in delegated event handlers. Typing those is the next step, before `strictNullChecks` is switched on.

Conventions:

- Drag gestures assign an object to `S.drag`. Its `move(p, e)` and `up(p, e)` get their types from `Drag`, so don't annotate them.
- Shared tables keyed by strings (`ICON`, `EXT_OF`, ...) are typed `Record<string, ...>`.
- Timers use `ReturnType<typeof setTimeout>`, so the code compiles with or without Node types.

## Deploying (GitHub Pages)

`.github/workflows/pages.yml` tests, builds and publishes `dist/` on every push to `master` (or on demand from the Actions tab).

One-time setup: **Settings → Pages → Build and deployment → Source: GitHub Actions**. Pages on a private repository needs a paid GitHub plan; otherwise make the repository public.

The site is served at `https://<user>.github.io/<repo>/`. The Vite `base: './'` setting makes asset paths relative, so no extra configuration is needed.

**Landing page:** `site/` holds the SVGcinema website that introduces the editor and links into it. `node site/build.mjs` builds `site/index.html`, which expects the editor in an `editor/` folder beside it; `npm run build:deploy` puts the two together in `deploy/` for any static host. The Pages workflow does not publish it yet. See [`site/README.md`](site/README.md).

## Toward a desktop app (Tauri)

The code is ready for a Tauri shell without changes. When it gets wrapped:

## Browser support

SVGcinema targets current Chrome, Edge, Firefox and Safari.

- **Save overwriting the same file** needs the File System Access API (Chrome and Edge). Other browsers download a fresh copy.
- **AVIF export** appears only where the browser can encode it.
- **Shape animation in CSS-only exports** (morphs, animated line ends, polygon / star corner radius) is written as SMIL `<animate>`, because Safari doesn't support the CSS `d: path()` property. With the hover trigger it stays `d: path()` (CSS pauses it on mouse out, which SMIL ignores), so in Safari those shapes don't move.
